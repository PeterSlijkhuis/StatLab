Some outcomes are counts: sick days, errors, visits, complaints. A count cannot be
negative, it comes in whole numbers, and its spread grows with its mean: people
who average one sick day vary less than people who average ten. The generalised
linear model from Lesson 15-2 handles this with a different family and the same
idea: put the linear part on a scale where a straight line makes sense.

The workplace data has no count, so this lesson adds one to the real employees:
sick days over a year, simulated so that they rise with workload and fall with
remote work.

<CodeBlock id="c-load" code={`library(dplyr)
library(broom)

d <- read.csv("data/workplace.csv", stringsAsFactors = TRUE)

set.seed(154)
d$sick_days <- rpois(nrow(d), exp(-0.2 + 0.18 * d$workload - 0.35 * (d$remote == "Yes")))

d %>% summarise(mean_sick = mean(sick_days), var_sick = var(sick_days), min = min(sick_days), max = max(sick_days))`} />

## The log link

Poisson regression models the **logarithm** of the expected count as a straight
line. Transforming back, each coefficient multiplies the expected count instead of
adding to it.

<CodeBlock id="c-fit" code={`m_sick <- glm(sick_days ~ workload + remote, data = d, family = poisson)

m_sick %>% tidy()
m_sick %>% tidy(exponentiate = TRUE, conf.int = TRUE)`} />

The first table is on the log scale, where 0 means no effect. The second is
exponentiated: these are **rate ratios**, where 1 means no effect.

- **`workload`**: about 1.20. Each extra point of workload goes with about 20 %
  more sick days.
- **`remoteYes`**: about 0.68. Remote workers have about two thirds of the sick
  days of office workers with the same workload, 32 % fewer.

Because the effects multiply, the same one-point increase in workload adds more
sick days at the high end than at the low end:

<CodeBlock id="c-predict" code={`predict(m_sick, newdata = data.frame(workload = c(2, 8), remote = "No"), type = "response")`} />

## Checking the Poisson assumption

A Poisson distribution has its variance equal to its mean. Real counts often vary
more than that, which is called **overdispersion**, and it makes the standard errors
too small. Estimate it from the Pearson residuals:

<CodeBlock id="c-dispersion" code={`sum(residuals(m_sick, type = "pearson")^2) / df.residual(m_sick)`} />

Near 1 is fine, as it is here. Clearly above 1, say 1.5 or more, and a negative
binomial model is the better choice; the model chooser shows how.

## The chi-square test is a Poisson model

In Module 9 you tested whether leaving the company depended on department with a
chi-square test. The same question can be asked of the **counts** in the table:
fit a Poisson model in which department and leaving each affect the counts but do
not interact, and ask how badly it misses.

<CodeBlock id="c-counts" code={`counts <- as.data.frame(table(department = d$department, left_company = d$left_company))
counts

m_independent <- glm(Freq ~ department + left_company, data = counts, family = poisson)

c(deviance = deviance(m_independent), df = df.residual(m_independent),
  p = pchisq(deviance(m_independent), df.residual(m_independent), lower.tail = FALSE))

chisq.test(table(d$department, d$left_company))`} />

The model without an interaction **is** the hypothesis of independence. Its
deviance is a likelihood-ratio chi-square, and it lands almost exactly on
Pearson's chi-square, with the same degrees of freedom. Adding the
`department:left_company` interaction would fit the table perfectly, so testing
whether that interaction is needed is the chi-square test. Once again, a classic
test turns out to be a question about a model.
