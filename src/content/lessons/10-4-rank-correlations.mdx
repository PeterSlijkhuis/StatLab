Pearson's *r* measures how well a **straight line** describes two variables. When
the pattern is curved but still steadily rising or falling, or when a few extreme
points pull the line around, a rank correlation is the safer description. It asks
a simpler question: when one variable goes up, does the other tend to go up too?

<CodeBlock id="c-load" code={`library(dplyr)

d <- read.csv("data/workplace.csv", stringsAsFactors = TRUE)

d %>% summarise(
  median_workload = median(workload),
  median_wellbeing = median(wellbeing),
  n = n()
)

c(
  pearson = cor(d$workload, d$wellbeing),
  spearman = cor(d$workload, d$wellbeing, method = "spearman"),
  kendall = cor(d$workload, d$wellbeing, method = "kendall")
)`} />

Three numbers, three definitions, one story: busier employees report lower
wellbeing. The sizes differ because the three coefficients measure different
things, so never compare a Spearman value from one study with a Kendall value from
another.

## Spearman is Pearson on ranks

Replace every score by its rank (1 for the lowest, 480 for the highest, ties share
the average rank) and compute an ordinary Pearson correlation. That is all
Spearman's *ρ* (rho) is.

<CodeBlock id="c-ranks" code={`c(
  spearman = cor(d$workload, d$wellbeing, method = "spearman"),
  pearson_on_ranks = cor(rank(d$workload), rank(d$wellbeing))
)`} />

Because only the order is kept, the exact distances between scores no longer
matter. A score of 9.9 and a score of 99 are both simply "the highest".

## Kendall counts pairs

Kendall's *τ* (tau) takes every pair of employees and asks whether they are in the
same order on both variables (a **concordant** pair) or in opposite orders (a
**discordant** pair). *τ* is the surplus of concordant over discordant pairs, as a
share of all pairs. A *τ* of −.28 means that, for a randomly chosen pair, the one
with more workload has lower wellbeing more often than not, by roughly 28 percentage
points. Kendall's *τ* is usually smaller than Spearman's *ρ* for the same data.

## What one extreme point does

<CodeBlock id="c-outlier" code={`set.seed(104)
x <- round(runif(12, 1, 10))
y <- round(x + rnorm(12, 0, 1.5), 1)

x2 <- c(x, 10)
y2 <- c(y, -20)

round(c(
  pearson = cor(x2, y2),
  spearman = cor(x2, y2, method = "spearman"),
  kendall = cor(x2, y2, method = "kendall")
), 3)`} />

Twelve points on a clear rising pattern, plus one far below the rest. Pearson's *r*
drops to about zero and even turns negative. The rank correlations still see the
rise, because the odd point is only one rank out of place, however far away it is.

## Testing and reporting

`cor.test()` takes the same `method` argument. With 480 employees and some tied
scores an exact *p* value cannot be computed, so ask for the normal approximation
with `exact = FALSE`, which is what R would fall back on anyway.

<CodeBlock id="c-test" code={`cor.test(d$workload, d$wellbeing, method = "spearman", exact = FALSE)`} />

Report *r*<sub>s</sub> (Spearman) or *τ* (Kendall), the sample size and the *p*
value. A rank correlation has no slope and no *R*², so there is nothing to predict
with: it describes an ordering, and only that.
